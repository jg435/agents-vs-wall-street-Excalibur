The task

Twelve numbers, four workbooks

The challenge fixes four companies and three reported figures each. Every figure has an exact label, an exact unit and an exact fiscal period, because a validator checks them against rows 7–9 of a supplied spreadsheet template.

The three metrics per company share a shape: a top line, an earnings-per-share figure, and one company-specific third measure — retail comparable sales, chip gross margin, Deere's largest segment, Hays' profitability.

Core rule

The number is computed, never hallucinated

Ask a language model for an EPS figure and it returns a plausible one. The leakage-free literature says that loses to a simple linear model. So the model here never produces a number at all.

The split is strict, and it is the single idea the whole system is built around:

  • The LLM reads. It searches the corpus, finds the right document, and returns a typed claim: a value, its units, the document it came from, and the sentence it came from.
  • Code verifies. A deterministic verifier accepts that claim only if the document exists, the quote actually appears in it, and the value is derivable from a number inside that quote under the declared unit conversion.
  • Code computes. Every forecast is plain arithmetic over verified facts. No model output is ever multiplied by anything.

The consequence worth noticing: a wrong answer from the model does not become a wrong forecast. It becomes a rejected fact, written to disk with the reason.

The pipeline

Six stages, and any of them can stop the run

01corpus Reads the frozen document set. Facts extracted with a receipt: value, document, verbatim quote.
02extractor LLM locates each declared fact and quotes it. Verifier accepts or rejects. Rejections are kept.
03consensus Public analyst estimates fetched the same day. Where none exists, the gap is named, not filled.
04contract One typed JSON per company: facts, consensus, known basis traps. The interface the engine consumes.
05engine + gates Twelve recipes compute the numbers. Six gates run before any cell is written.
06workbook Fills only the forecast cells of the supplied templates. Loud failure on any label or period mismatch.

Each stage writes to disk, so the final run is reproducible from cache and does not depend on a live model call. The one thing that must be fresh is consensus — and there is a gate that enforces it.

The engine

Consensus anchors, guidance moves it

The forecasting judgement reduces to one rule, applied wherever both a market consensus and a management guide exist.

# the anchor rule
forecast = consensus + 0.8 × (guidance − consensus)

# no consensus available → guidance becomes the anchor
forecast = guidance

Consensus is the starting point because it is hard to beat on raw information at a one-quarter horizon. Guidance is the adjustment because management knows the quarter better than the street does — but the street has usually already priced part of it, so the guide is taken at a fraction, not in full. The gap is signed both ways: a guide below consensus pulls the forecast down.

Three tiers, labelled on every number

  • TIER 1  consensus anchor, guidance adjustment. The default.
  • TIER 2  guidance is the anchor — no public consensus exists for this measure.
  • TIER 3  derived from an identity: a profit built from sales × margin, an EPS built from net income ÷ shares.

Where guidance is annual and the forecast is quarterly

Home Depot and Deere guide the full year only. A full-year guide cannot be dropped onto one quarter unchanged, so it is pulled toward what the most recent quarter actually did:

temper(fy_guide, last_quarter_actual) = mean of the two

# Home Depot EPS: the FY guide said roughly flat-to-up,
# but Q1 EPS actually printed DOWN 3.7% year on year
temper(+2.0%, −3.7%) = −0.83%   → applied to the Q2 FY25 base

# comparable sales gets tempered twice — the April monthly
# figure had already flipped negative
temper(temper(+1.0, +0.6), −0.5) = +0.15pp

The rule is deterministic and stated in advance. It is not a knob turned until the answer looked right.

Amendment 6

The gates: six ways the run refuses

This is the part that distinguishes the system from a research script. Before a single cell is written, six checks run. Any failure raises and the run stops — it never degrades to a guess and never leaves a blank.

consensus freshness Fails if the estimate cache is not from today. Analyst estimates move; a stale anchor silently poisons every Tier 1 number.
revision diff Fails if the engine is using anything but the newest vintage of a guide. Every guidance statement is swept across the whole corpus to build a dated series, so a revision is caught mechanically rather than remembered.
period + basis schema Fails if a fact's fiscal period or accounting basis is not allowed to feed that metric. An adjusted figure cannot feed a GAAP metric; a prior-year quarter cannot pose as a guide.
one-off companion Fails if a figure carrying a known one-off item is the sole anchor. A quarter flattered by a tariff refund may inform a forecast, but it may not be the whole basis for one.
sanity range Fails if a forecast lands outside a plausible band declared per metric in advance — a bound on arithmetic slips, not a forecast in disguise.
all-twelve seam Fails, by name, if the engine produced no forecast for a required metric. A missing number surfaces as an error rather than an empty cell in an uploaded workbook.
What the revision gate was built for

Hays guided a 38% effective tax rate in August, then revised it to 45% in February. Reusing the older figure would have inflated EPS by roughly a tenth with nothing visibly wrong. The gate compares the engine's fact against the newest vintage found anywhere in the corpus and stops the run on a mismatch.

A seventh rule sits underneath all of them: a required fact that is missing raises immediately rather than defaulting to zero. There is no path through the code where an absent input quietly becomes a number.

Receipts

Every figure carries its own audit trail

Each of the twelve forecasts writes a structured receipt: the value, the formula in words, every fact it consumed with that fact's period, basis, source document and one-off flags, and the list of gates it passed.

// one fact, as stored
{
  "value": 46.0,
  "period": "FY2026",
  "basis": "PRE-EXCEPTIONAL",
  "doc": "challenge/offline-data/hays/filings/2026-07-…md",
  "quote": "…expects to be at the top of the £37.0–46.0m consensus range",
  "is_latest": true,
  "revised_since_prior": false,
  "one_offs": []
}

Absent is deliberately not the same as false. Every fact must carry all nine schema keys explicitly — a missing one_offs field is a schema violation, not an empty list — because the difference between "we checked and there were none" and "nobody looked" is the whole point.

Rejected claims are written to disk too. Seven facts were refused in the final run, each with the reason it failed verification. A system that can show you what it threw away is making a stronger claim than one that only shows what it kept.

Traps

Two places the obvious number is the wrong one

Both were caught by reading the metric definition rather than trusting the data feed — and both are recorded in the company contract so the engine cannot forget them.

Deere: the consensus is measuring something else

The public revenue consensus is around $10.7bn, and the metric asks for worldwide net sales and revenues. Those are different things: the feed covers equipment operations only, while the required figure includes financial services — roughly $1.6bn a quarter. Anchoring on the feed directly would have understated the top line by more than ten percent. The engine adds an explicit finance-revenue bridge taken from Deere's own most recent actual quarter, and the receipt labels it an estimate.

Analog Devices: the street already priced the beat

Consensus sits at $3.33 EPS on $3,925m of revenue. Management guided $3.30 on $3,900m. Consensus is above the guide, meaning the street has already priced ADI's habit of beating its own guidance. Re-adding a beat adjustment on top would double-count it. Because the gap rule is signed, the engine tilts gently downward toward the guide instead — the correct behaviour falls out of the rule rather than needing a special case.

Limits

What this does not establish

The system is careful about provenance. It is much thinner on demonstrated accuracy, and the distinction matters.

  • The historical replay is close to empty. It was built to compare recipe shapes against naive alternatives without lookahead, and to measure error variance. In practice only the Analog Devices replay produced a scoreable series, at four observations. The Home Depot and Deere replays extracted too little from the corpus to score at all. The forecasts are defensible on method; they are not yet backed by out-of-sample evidence.
  • The 0.8 weight is a judgement, not a fitted parameter. With a replay this thin it could not have been calibrated, and it is applied uniformly across companies and metric families.
  • Consensus is a reconstruction. Scoring is against a frozen consensus the team cannot see; the public feed is the closest available proxy, and for Deere it measures a different quantity entirely.
  • Coverage is uneven. Six of the twelve numbers have no public consensus at all and rest on guidance or a derived identity, where the anchor rule does less work and the accounting has to be right on its own.
  • The README describes an earlier structure. It documents a tier1/ and tier2/ layout; the shipped system is the agent/ package described here.

None of these are hidden in the repository — the replay prints its own coverage, the consensus gaps are stored with the reason each one is empty, and the rejected facts are committed. That is the same instinct as the gates, pointed at the system's own claims.
